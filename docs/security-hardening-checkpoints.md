# Security hardening checkpoints

These 27 audit fingerprints are source-backed engineering candidates, not confirmed vulnerabilities. A code change here does not upgrade an audit verdict. Focused tests require the Cloudflare security-audit skill's OS-enforced execution sandbox. The default `sandbox-exec` call was denied, the escalated call lacked a working memory limit, Docker and Colima were not running, and macOS rejected both `ulimit -v` and `ulimit -d` memory caps. Target tests and builds have not run. Static Python parsing and `git diff --check` passed.

On 2026-11-09 the user directed application to the production Supabase project after declining the paid development branch. The connected PictureMe database accepted `security_authority_guards` (remote version `20261109165624`) and `harden_trigger_search_paths` (`20261109165829`). Read-only verification found the new tables, enabled triggers, service-role-only RPCs, the private `face-profile-images` bucket with a 10 MiB cap, and SELECT-only browser grants on the eight backend-owned product tables. The new trigger search-path advisor warnings cleared. This is a live schema deployment, not an isolated race test or a backend/frontend deployment.

Account deletion was not implemented in the starting repository. The user confirmed that deletion removes avatars and enrollment assets, retains event photos, and transfers each owned event to an active admin. `DELETE /api/account` preflights successor availability before media cleanup. A database RPC rechecks and atomically transfers every owned event to its longest-serving active admin, updates collection reservation ownership, removes the departing organizer's membership, and anonymizes retained photo attribution before deleting the Auth user. An event without an active admin returns `ACCOUNT_EVENT_TRANSFER_UNAVAILABLE` (409). The `RESTRICT` foreign keys from created events and uploaded photos to users remain intact. Python fixtures for success, no successor, and preflight-to-transfer revocation are written but unexecuted. The RPC and its race behavior still need isolated database validation before backend deployment. Read-only live schema inspection confirmed `auth.users.deleted_at` and `banned_until` before applying the migration.

## Required release validation

The two migrations are applied in production. Read-only checks confirmed migration history, `to_regclass` for the new tables, `information_schema.columns`, private bucket settings, enabled triggers, service-role-only RPC execution, SELECT-only browser product-table grants, RLS policies, and no `photos` or `user_photo_matches` Realtime publication. No provider mutation or live user-data test was performed. Before deploying the backend and frontend, use an isolated disposable database with dummy users and low limits to verify token-bound join, organizer grant, role change and removal, trigger races, and organizer transfer. Check that a simultaneous join cannot undo removal, a second join reports no new membership, a repeated grant does not demote an admin, and an organizer revoked before a write cannot commit it. Coordinate deployment because the old browser direct-upload contract now returns `410`.

The post-migration Supabase security advisor no longer reports mutable search paths for the new triggers. It still reports five expected service-role-only tables [without browser RLS policies](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy) (three new and two preexisting), seven preexisting [callable `SECURITY DEFINER` functions](https://supabase.com/docs/guides/database/database-linter?lint=0028_anon_security_definer_function_executable), and the Auth [leaked-password-protection setting](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection). Review those separately; they were not changed by these migrations.

Confirm every deployed direct-upload signer is disabled and the last issued Cloudinary signature has expired, or rotate the provider secret. Review old enrollment, cover, avatar, and any user-owned Supabase Storage objects in provider inventory through an owner-controlled process; Supabase Auth deletion can fail while a user owns Storage objects. Configure ingress request logging to omit join/gallery token paths and set an upstream body cap. Record the number of matching workers or add distributed concurrency admission before treating the process-local semaphore as a global cost limit. Validate organizer transfer in a disposable database with multiple owned events, no eligible admin, admin revocation between preflight and transfer, and Auth deletion failure before enabling organizer account deletion.
